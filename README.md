## 三、本构建做了什么

在保留原项目全部功能的前提下，做了以下修改：

### 3.3.1：发版自动化 + 仓库清理

- **打 tag 即自动发版**：`git tag v3.3.1 && git push origin v3.3.1` → CI 跑单测、用固定签名打
  `alphaRelease`、**校验 `versionName` 与 tag 一致**、建 Release 并把 4 个 APK 全挂上去。
  以前这一步是纯手工（下载 139MB artifact → 手工建 Release → 逐个上传），既慢又容易混用不同构建的产物。
- **删除无人引用的 `core:ffmpeg` 模块**及其校验插件（native CMake/NDK 代码，`settings.gradle.kts`
  里早已注释掉、app 也没有任何引用）—— 去掉一块"永远编译不到却要维护"的死代码。
- 新增 [`docs/真机验证清单.md`](docs/真机验证清单.md)：把真机验证的检查点（含这台机器上
  MediaStore 的四个怪癖）固化下来，以后每次发版照着跑。

### 3.3.0：改名 BDT · 下载交付链路重写 · 重复文件清理

**改名**：应用显示名与全部界面文案由「哔哩下载器」改为 **BDT**（12 个语言资源 + 6 处代码文案，
共 99 处）。包名与签名保持不变，**可直接覆盖安装、登录状态与设置都不丢**。

> 下载目录仍沿用 `Download/BiliDownloader` —— 这是为了让**你已经下好的文件继续被找到**
> （记录里存的是完整路径）。要不要连目录一起改成 `Download/BDT`，可以单独再说一声。

**下载交付链路重写（这一版最核心的修复）**

以前"重新下载同一集"会不断在下载目录里攒出 `xxx (1).mp4`、`xxx (2).mp4` 整集大小的副本，
严重时**刚下好的文件会被删掉、界面却报失败**。根因是真机（小米 / Android 16）上 MediaStore 的四个怪癖：

| 现象 | 实测 |
|---|---|
| 写入撞名 | 自动改名为 `xxx (1).mp4`，不报错 |
| 事后改名 | 继续往 `(N)` 上加；`_data` 与回读名还可能和磁盘对不上 |
| 删除/改名/读属性 | app 对"媒体库拥有的文件"既 `stat` 不了也删不动（EACCES）；`File.listFiles()` 甚至可能返回 null |
| 日志 | MIUI 会过滤 app 自己的 logcat，同一段代码有时一条日志都没有 |

现在的做法（**"挪开 → 写入 → 删除"三段式**）：

1. **交付前**先把同名旧文件挪到一边（有「所有文件访问」就直接改名；没有就让媒体库改行名）——
   此刻新文件还没写，**物理上不可能误删自己**；
2. 写入新文件：正式名此刻是空闲的，**不会再被改成 `(N)`**；
3. 成功就删掉挪开的那份；**失败就把旧文件改回原名**，用户原有的东西一个不少；
4. 目录枚举一律**问 MediaStore**（`RELATIVE_PATH` 前缀 → `_data` 前缀），并支持
   `scanFile` 单名探测/扫目录兜底 —— 不再依赖 `listFiles()`。

**新增：重复下载文件检查/清理**

- 下载管理页常驻入口：发现"同一部视频多份副本"时列出来，**默认保留正式名那份**，由你勾选删除；
- 清理"不是本 App 拥有"的副本（上一版安装留下的、别的 App 写进来的）时，会走
  **系统确认框**（Android 11+ 的规矩），而不是静默失败；
- 可选「所有文件访问」权限：给了之后交付阶段可以直接改名/删除，这台机器上的 `(N)` 问题彻底消失。

**新增：诊断轨迹文件**

交付与清理的每一步都会写进 `Android/data/com.whyd9527.bilibilias/files/logs/download-trace.log`
（超过 256KB 轮转）。起因就是上面那条"MIUI 过滤日志"——**没有它，这类"删除没生效"的问题只能靠猜**。

**其它一大批修复（42 条高中低危，逐条带证据）**

取消不再被记成失败、Cookie 不再外发到非 B 站主机、封面下标算错导致合并必失败、
命名规则吃掉标题下划线、抽帧 OOM 与无上限、列表 key 重复会崩、隐私门槛统一、
DataStore 损坏兜底、合并进度单位、多语言小数点、首页板块补齐落盘……
清单与证据见 [`docs/bug-report-v324.md`](docs/bug-report-v324.md) 与
[`docs/项目交接文档.md`](docs/项目交接文档.md) 第十四节。

**数据库**

- `download_task(platform_id, type)` 加**唯一索引**（版本 4 → 5），迁移时**先去重再建索引**，
  避免老库升级即失败。

### 3.2.4：文件命名与附加内容的两批修复

- **字幕文件终于带上后缀了**。以前下载的字幕叫 `某番剧_第1话_zh-CN`（没有后缀），
  看不出是什么格式、别的 App 也认不出来；现在是 `某番剧_第1话_zh-CN.srt`。
- **文件名不再吃掉你标题里的下划线**。命名规则里那个"把多余下划线合并成一个"的兜底
  做过了头 —— 标题或合集章节名里本来带 `_` 时会被一起删掉。现在只收拾"因为某个字段为空
  而多出来的分隔下划线"，**你内容里的下划线一个都不动**。
- **内嵌封面/字幕用完就清**。合成视频时落到缓存里的封面与字幕临时文件，以前只有
  「存储管理 → 清空缓存」才删得掉，现在下完一集就清掉，应用启动时也会顺手扫一遍残留。
- **BV 号解析补上一条一直没生效的兜底**。普通视频页里没有 `bvid` 字段时，程序会退回
  "按节点反查"，而这条兜底**从写下来那天起就没执行过**（原实现把它放在了一个不会触发的
  分支里）。修好之后，走「TV 解析平台」时请求里能带上正确的 BV 号。
- 剪贴板自动识别：**隐私门槛两处统一**（只有明确同意过才会读剪贴板，此前"已拒绝"和
  "还没选"都会被读、解析页甚至完全没有门槛），并且**识别成功后不再清空你的剪贴板**
  （以前会把刚复制的内容弄没，让你没法粘到别处）。

### 3.2.3：续传写文件的一处隐患

- **续传时如果服务端忽略 `Range`、把整份文件当 200 回给你，旧实现会把它"追加"到已经下了
  一半的文件后面** —— 结果是**长度翻倍、内容错位**的坏文件，状态却还显示"已完成"。
  现在会先判断服务端是不是真按 `Range` 回了（206 且起点对得上），不是就**从头重下**：
  宁可多下一次，也不拿一个坏文件糊弄你。绝大多数 CDN 都是规矩的，这条是给"万一"兜底。
- 顺带把下载列表的内部 key 从"哪一集"改成"哪条记录"，避免出现重复条目时界面崩溃。

### 3.2.2：重新下载同一集的修复

- **同一集重新下载不再产生重复记录**。以前「已完成下载」里会出现**两条同名条目**，
  其中一条点开提示"文件不存在"—— 因为落盘文件名是固定的，后一次下载覆盖了同一个文件。
  现在同一集只保留一条记录，重新下载就更新它。
- **重新下载不再在下载目录里留下 `xxx (1).mp4` 副本**。以前"替换同名文件"那一步
  （按 `DISPLAY_NAME` + `RELATIVE_PATH` 查）实际上**从来没匹配上**（MediaStore 存的
  `RELATIVE_PATH` 带结尾斜杠），于是旧文件不删、MediaStore 只好把新文件自动改名成
  `xxx (1).mp4` —— 每重下一次就多攒一份整集大小的副本。
  现在改成 **先把新文件完整写出来 → 再删同名旧文件 → 最后改回正式名**；
  中途任何一步失败都会回滚新文件，**你原来那份不会丢**。

### 3.2.1：下载链路的一批健壮性修复

对「自动解析链接 → 下载视频」做了一轮全链路审查（逐条带"文件:行 + 触发 + 后果"）
＋ 两批真机验证。修掉的是这几类：

**不再有"假失败 / 假成功"**

- 暂停 / 取消下载**不再被记成「下载失败」**（原先会白重试 5 次、最后报错并弹提示）；
- 只勾封面 / 弹幕 / 字幕、**不勾媒体流**时不再必然报错（原先没有媒体文件也去走合并）；
- 合并后的成品**先移动成功、才删源文件**（原先移动失败会让源文件先没了，只能整集重下）；
- 单文件（durl）资源**不再丢音轨**（原先会产出无声视频、状态还是「已完成」）。

**失败不再静默**

- 解析失败（没识别出链接 / 短链展开失败 / 番剧接口报错）现在会显示**带「重试」的错误卡片**，
  不再停在空白页；
- **同一段文本可以重新解析**（原先"再粘一次"和"点重试"都毫无反应）。

**不会崩、也不会拖垮整集**

- 剪贴板里的超长数字（`av1234567890123456789012345`）**不再崩进程**；
- 非 B 站文本（例如 `会议记录 ss123 已上传`）**不再被误判**成 B 站链接并下载无关视频；
- 标题含英文双引号**不再让合并必然失败**；
- 番剧剧集列表为空时**不再越界崩溃**；
- 没有封面地址时**不再请求空 URL** 把整集拖垮。

**状态与磁盘**

- 重启时未完成的下载会被**明确清理并告知**（不再留下看不见、也恢复不了的"幽灵任务"）；
  被中断的分片会保留，重新添加同一内容时**接着下**；
- 失败任务的临时文件会被清理；下载结束后前台服务与「缓存通知」正常收尾；
- 「已完成下载」里只下弹幕 / 封面 / 字幕的记录，不再显示成「音视频 / 未知画质 / mp4」
  （那会让人以为视频已经下好了）。

**其它**

- 多线程分片下载可在设置里开关并调并发数（2 / 4 / 6 / 8）。

### 修复了「开箱即编译失败」

- **移除百度统计 SDK**。其 jar 由构建脚本从作者私有地址现下，该地址已返回
  **403**；而源码无条件 `import com.baidu.mobstat.StatService`，导致编译失败。
- **修复 CI**：替换已废弃的 `gradle-build-action@v3`；移除对 fork 中不存在的
  `ALPHA_KEYSTORE_*` secrets 的强依赖，改为「有则用、无则回落」。

### 修复了下载必然失败

- 原代码在「解析平台 = TV」时会把媒体 CDN 请求的 `User-Agent` 与 `Referer`
  **一起删掉**。而 B 站 CDN 实测对请求头极敏感：

  | 请求头 | 结果 |
  |---|---|
  | 浏览器 UA + Referer | ✅ 206 |
  | 浏览器 UA，无 Referer | ❌ 403 |
  | BiliApp UA + Referer | ❌ 403 |

  结果就是走这类 CDN（如 `*.edge.*` 节点）的番剧下载全部 403。
  现已改为**无条件补齐请求头**。

- **移除已失效的漫游代理**。作者自建的 `bili-api.misakamoe.com` 实测
  返回 `-404` / `-412 请求被拦截`，继续使用会让番剧解析与下载全部失败，
  已改为直连。

### 下载失败不再「静默」

- 原代码下载失败只抛一个 `Exception("下载失败")`，随即被 `printStackTrace()`
  吞掉，界面上只剩一个「错误」。现改为**记录完整原因并弹提示**，例如
  「解析视频流失败（可能是接口变化，或该内容需要登录/大会员）」。
- 下载执行器现在会**校验 HTTP 状态码**——此前 CDN 返回 403 时，
  错误页正文会被当成视频写进文件并报告「下载成功」。

### 账号与隐私

- **扫码登录不再经过第三方服务器**。原实现把二维码内容发给
  `pan.misakamoe.com` 换取图片，而该内容含 `qrcode_key`（实测确认），
  它是轮询换取登录 Cookie 的凭据，等同于登录口令。现改用 ZXing 本地渲染。
- **彻底移除 Firebase / Google Analytics / Crashlytics**，删除
  `google-services.json`；移除向作者服务器上报下载记录（含用户名与 UID）的功能。
- `allowBackup` 由 `true` 改为 `false`，并补全备份排除规则。
- 明文 HTTP 通道（SSE 80 端口）改为 HTTPS。

### 其他

- 换皮：应用名、包名、图标。
- 修复存储管理页「授权后仍提示未授权、已下载大小恒为 0 B」
  （根因是同一个配置文件被创建了两个 DataStore 实例，读取方永远读到旧缓存）。
- 移除原作者捐赠入口、QQ 频道 / QQ 群链接、失效的隐私政策外链。
- 清理死代码（1985 行的废弃 `DownloadManager`）、修复 3 处 `GlobalScope` 协程泄漏、
  修正包名拼写 `weight` → `widget`。

## 五、功能

- **登录**：扫码登录、Cookie 登录
- **解析平台**：Web、TV
- **解析类型**：普通视频、番剧影视、互动视频、充电视频（依赖账号会员态）
- **输入来源**：AV / BV / EP / SS 链接、系统分享、投稿 / 收藏夹 / 最近观看 /
  点赞 / 追番列表、内置网页解析
- **下载**：内置下载器（断点续传、任务队列、前台服务通知）、
  ASS / SRT 字幕下载、视频逐帧导出
- **其他**：13 种语言、Material You 配色、手机 / 平板自适应布局

## 六、自行构建

需要 JDK 17+、Android SDK Platform 36。

```bash
git clone https://github.com/whyD9527/BDT.git
cd BDT
./gradlew :app:assembleAlphaRelease
```

产物位于 `app/build/outputs/apk/alpha/release/`。

仓库已配置 GitHub Actions：推送到 `main` 或手动触发
`Build APK (Alpha)` 即可自动出包。
